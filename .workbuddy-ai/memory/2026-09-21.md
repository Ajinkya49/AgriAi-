## ⚠️ `next build --webpack` silently disables `proxy.ts` — found and fixed

Initial alarm ("`proxy.ts` never runs") was **too broad**. Corrected after tracing
`NextNodeServer.loadNodeMiddleware()`.

For a **Node-runtime** proxy on Next 16, `middleware-manifest.json` staying empty
is *expected* — the runtime does not read it for this case. The real path:

1. read `.next/server/functions-config-manifest.json`
2. if it declares `/_middleware`, `require('.next/server/middleware.js')`
3. if that throws `MODULE_NOT_FOUND`, **swallow it** and return `undefined`

| Build | Declares `/_middleware` | Emits `middleware.js` | Proxy runs |
|---|---|---|---|
| `next build` (Turbopack, default) | yes | **yes** | ✅ |
| `next build --webpack` | yes | **no** | ❌ |

Both bundlers write the declaration; **only Turbopack emits the file it points
at.** The `require` fails, step 3 hides it — no build error, no runtime error.

**My earlier reasoning error:** I read the empty `middleware-manifest.json` as the
smoking gun and concluded middleware never ran, then "confirmed" it with a 200
from `/dashboard`. But that 200 came from a `--webpack` build, so the conclusion
held for the wrong reason and I generalised it to all builds. The decisive check
is `functions-config-manifest.json` + the presence of `middleware.js`, not the
manifest.

**Verified fixed** — Turbopack build, `next start`, unauthenticated:

```
/  /login  /signup           -> 200
/dashboard /upload /assistant
/community /profile /settings /onboarding  -> 307 -> /login?redirect=…
```

**Guard added:** `frontend/scripts/verify-proxy-registered.mjs`, wired as
`postbuild`. Tested to pass on Turbopack and fail on `--webpack` with an accurate
diagnosis. **Vercel runs `npm run build` (Turbopack), so deploys were never
affected.** Remove `--webpack` if it appears anywhere.
