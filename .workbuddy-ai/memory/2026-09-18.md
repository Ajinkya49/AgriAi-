### Mechanical sweeps (all verified after)

- `bg-white` → `bg-surface-2` — 60 occurrences, 26 files. The light theme leaned on
  `bg-white` rather than a token, so no token change could darken cards.
- 43 card instances of `border-border … border bg-surface-2` → `.glass`. The regex
  refuses to swallow layout classes.
- Solid `bg-primary` → `bg-accent` (18). **⚠️ `\bbg-primary\b` also matched
  `bg-primary-soft`** — a hyphen is a word boundary — corrupting 14 tokens. Reverted;
  use `bg-primary(?!-)`.
- All 10 form-field class strings → the single `.input` rule.

### ⚠️ Bug found in the e2e contrast check

`ui-audit.mjs` computed contrast by returning the **first non-transparent
background**. Correct while every surface was opaque `bg-white`; with `.glass` at
`rgba(255,255,255,0.03)` it read a 3% white overlay as **pure white** and reported
light-on-dark text as **1.10:1**. Fixed by compositing alpha up to the first opaque
ancestor. Contrast now passes for real.

Also updated the design-token assertions, which encoded the old palette by value —
a deliberate spec change, noted in `DECISIONS.md` §11.6 so it isn't mistaken for a
loosened test.

### ⚠️ The landing page had never been accessibility-checked

The tap-target / contrast / icon-pairing checks sat inline in `ui-audit.mjs` and
therefore only ever ran against whatever page was loaded — always a signed-in
screen. Extracted them into an `auditAccessibility(page)` helper and now assert
against **both `/` and `/dashboard`**. It found four real defects immediately:

- Footer links **36px** tall (`min-h-[2.25rem]` hand-written instead of the token)
- Footer "Log in" **41px** wide (short text link, no horizontal padding)
- Nav and footer logo links **32px** tall (wrapped a `size-8` icon, no minimum)
- Flow-diagram step number at **1.21:1** — drawn in `--color-border`, i.e. the same
  colour as the card edge, so it was effectively invisible

The audit was also under-measuring contrast: it composited the *background* alpha
but dropped the *foreground* alpha, so `text-primary/70` was measured as fully
opaque. Text is now composited over its background first.

### Post-review polish

Reviewing the remaining screenshots (not just the ones I'd already looked at) caught
four things, all fixed:

- The active Natural/Traditional chip was a **solid** `bg-natural-text` — accessible
  but a glaring light block in a dark UI. Now a tint plus a ring.
- The floating bottom tab bar at 82% opacity let card text show through it. Added
  `.glass-nav` (96%) plus a gradient fade so content dissolves before it reaches
  the bar.
- `.input` was too close to the card behind it to read as a field; lifted the
  border and fill.
- The closing CTA and the footer both added bottom spacing — ~200px of dead space.
  Dropped the footer's top margin.
- `Eyebrow` pills stretched to full width inside a flex column (`align-items:
  stretch` beats `inline-flex`). Added `w-fit`.

A second pass over the remaining screenshots (mobile settings, assistant,
community, features) found one more:

- **The crop checkboxes rendered as bright green squares.** Two causes: the browser
  default accent colour, and an explicit `accent-confidence-high` on the input —
  the *confidence-band* green, semantically wrong for a checkbox and clashing with
  the violet highlight on its own label. `globals.css` now pins
  `input[type=checkbox|radio]` to the violet accent; the per-component class is
  gone.

Note: `/onboarding`'s crop checkbox is deliberately `sr-only` with the chip as the
real 44px target, so it must NOT be added to the tap-target audit as-is — a
visually-hidden input measures 1×1 and would false-positive.

## Pre-launch — solutions review pack

The agronomist-review gate was recorded as the biggest remaining risk in three
places, but there was nothing to hand a reviewer: the 50 rows were only readable as
one 23 KB SQL `insert` statement.

Wrote `supabase/scripts/export_solutions.py` → `docs/solutions-review/`
(printable HTML grouped by disease with Approve/Amend/Remove boxes, a CSV with
blank verdict columns, and raw JSON). It spins up the embedded Postgres and queries

stops applying.

entries in the product. Now flagged in the sheet and in `DEPLOYMENT.md` §7.
