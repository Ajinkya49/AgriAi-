### ⚠️ Key learning: you cannot INSERT into auth.users on hosted Supabase

Direct `INSERT INTO auth.users` (fine against local Postgres, and what
`seed.sql` does) produces users that **cannot sign in** on a hosted project.
Sign-in fails with the opaque:

```
{"code":500,"error_code":"unexpected_failure","msg":"Database error querying schema"}
```

Root cause: GoTrue v2 resolves email/password logins through **`auth.identities`**,
which had **0 rows**. The fix is the supported Admin API —
`POST /auth/v1/admin/users` — which creates the `auth.users` row, the
`auth.identities` row and the bcrypt hash together.
